# برج HTML

> **اجعل تعليم HTML متاحاً للجميع — بغض النظر عن الأجهزة، أو الاتصال بالإنترنت، أو عمر الجهاز.**

**برج HTML** هي منصة تعليمية مبسطة مصممة للعمل دون اتصال بالإنترنت (Offline-First)، تهدف إلى تعليم أساسيات HTML من الصفر. يتم استضافة التطبيق بالكامل داخل ملف `.html` واحد ومستقل بدون أي تبعيات خارجية، أو أطر عمل، أو خطوات بناء، أو متطلبات خادم.

## 🎯 فلسفة التصميم والمهمة الأساسية

### المشكلة التي نحلها
تقدم معظم منصات تعلم تطوير الويب الحديثة حواجز كبيرة:
1. **الاعتماد على الاتصال بالإنترنت**: تفشل بيئات التطوير المتكاملة (IDEs) ومنصات إدارة التعلم (LMS) عبر الإنترنت في البيئات ذات النطاق الترددي المنخفض أو غير المتصلة بالإنترنت.
2. **متطلبات الأجهزة الحديثة**: تتطلب الأدوات الحديثة أنظمة تشغيل حديثة، وذاكرة وصول عشوائي (RAM) عالية، ومحركات متصفح ثقيلة، مما يستبعد المستخدمين الذين يمتلكون أجهزة قديمة.
3. **عبء التعقيد**: غالباً ما يغمر المبتدئين بأدوات البناء، وأطر العمل، ومديري الحزم قبل كتابة سطر واحد من HTML.
4. **تقييد المورد (Vendor Lock-in)**: يعتمد تقدم المستخدم على توفر منصة الطرف الثالث والإنشاء الإلزامي للحسابات.

### حلنا
يعمل برج HTML بناءً على أربعة التزامات أساسية:
* **إمكانية الوصول قبل الميزات**: إعطاء الأولوية للتوافق الأساسي والقراءة الواضحة على أطر عمل واجهة المستخدم.
* **التعليم على حساب الترفيه**: تقدم منظم طابقاً بطابق حيث يتم اكتساب الإتقان من خلال تقييم صارم وعادل.
* **الملكية بدلاً من المنصات**: يمكن للمستخدمين امتلاك المشروع، وتنزيله، وتعديله، وتشغيله إلى أجل غير مسمى دون طلب إذن.
* **الوضوح بدلاً من التعقيد الذكي**: مكتوب بشفرة واضحة ومقروءة بدون تشفير أو تحويل (Transpilation) بحيث يمكن للمتعلمين الفحص والتعلم مباشرة من الكود المصدري نفسه.

## ✨ الميزات الرئيسية

* **100% دون اتصال بالإنترنت (Offline-First)**: يعمل محلياً في أي متصفح ويب دون الحاجة إلى الوصول للشبكة.
* **بنية الملف الواحد**: كل شيء (CSS، JS، المحتوى) موجود داخل ملف `index.html` واحد محمول (~50 كيلوبايت).
* **دعم المحركات القديمة**: مبني باستخدام JavaScript آمن للأنظمة القديمة (معيار ES3/ES5) لضمان التشغيل الفعال على الأجهزة القديمة.
* **بدون تبعيات**: خالي من المكتبات الخارجية، مديري الحزم، الخطوط، أو روابط شبكات توصيل المحتوى (CDN).
* **نظام رموز المستويات**: آلية بسيطة لتجزئة كلمات المرور تسمح للمستخدمين باستئناف تقدمهم عبر أي متصفح أو جهاز دون الحاجة إلى التخزين المحلي.
* **سمات الطرفية (Terminal Themes)**: أوضاع بصرية قابلة للتخصيص (Matrix، Amber، DOS Blue، Light، Cyber) يمكن الوصول إليها مباشرة من الواجهة.

## 🚀 البدء

1. قم بتنزيل أو حفظ ملف `index.html` على جهازك.
2. انقر نقراً مزدوجاً فوق `index.html` (أو افتحه باستخدام أي متصفح ويب).
3. اقرأ التعليمات الخاصة بالطابق الحالي، واكتب كود HTML الخاص بك في حقل الإدخال، ثم انقر فوق **تحقق من الكود (CHECK CODE)**.
4. عند إكمال الطابق، قم بتدوين أو نسخ **رمز المستوى (Level Code)** الذي تم إنشاؤه لاستئناف تقدمك في الجلسات المستقبلية أو على أجهزة مختلفة.

## 🏗️ البنية والآليات

يفصل ملف `index.html` الواحد بشكل صارم منطق التشغيل عن المحتوى التعليمي مع الحفاظ على بيئة خالية من التبعيات:


index.html
├── <head>
│   └── <style> : أنماط الطرفية، التخطيطات المتجاوبة، السمات البصرية
└── <body>
├── حاوية واجهة المستخدم : شاشة اللعبة، طرفية الإدخال، عرض المخرجات
└── <script>
├── مصفوفة المستويات [] : بيانات تعليمية نصية وقواعد التحقق
└── منطق المحرك   : تحديثات DOM، التحقق من رموز المستويات، حالة التقدم

### التزامات التصميم
- **CSS مضمن (Inline)**: مضمن داخل كتلة `<style>` واحدة.
- **JavaScript مضمن (Inline)**: مضمن داخل كتلة `<script>` واحدة.
- **معيار ES3/ES5**: يستخدم هياكل الحلقات القياسية وصيغة ES3/ES5 (`var`، حلقات `for`) بدلاً من ميزات ES6+ الحديثة التي تتطلب تحويلاً (Transpilation).

## 🔑 نظام التقدم برموز المستويات

بدلاً من الاعتماد على واجهات برمجة تطبيقات التخزين في المتصفح (`localStorage`، أو `indexedDB`، أو ملفات تعريف الارتباط Cookies)، يتم حفظ التقدم عبر **رموز مستويات (Level Codes)** قصيرة وقابلة للقراءة البشرية.

### كيف تعمل
1. عند إكمال طابق، يعرض التطبيق رمزاً فريداً (مثال: `L5-PARA`).
2. يمكن للمستخدمين نسخ الرمز، أو حفظه، أو تدوينه.
3. في الجلسات اللاحقة، يؤدي إدخال الرمز في حقل **الانتقال إلى الطابق (JUMP TO FLOOR)** إلى تحميل حالة ذلك الطابق على الفور.

### الفوائد
- **التوافق عبر المتصفحات والأجهزة**: الانتقال بسلاسة بين هاتف محمول قديم وحاسوب مكتبي.
- **بصمة خصوصية معدومة**: يعمل بدون تتبع المستخدمين، أو تخزين ملفات تعريف الارتباط، أو إجراء طلبات ويب.
- **بدون تبعيات لواجهة برمجة التطبيقات (API)**: يعمل على متصفحات تم إنشاؤها قبل وجود مواصفات التخزين المحلي.

## 🛠️ إرشادات التخصيص والتوسيع

نظراً لأن منطق التطبيق بالكامل مخزن في مصفوفة JavaScript نظيفة، فإن إضافة أو تعديل الطوابق يتطلب فقط تحرير مصفوفة `levels` داخل ملف `index.html`.

### إضافة طابق جديد

```javascript
{
    id: "L52-HEADER",
    title: "Floor 52: Header Semantic Element",
    info: "The <header> tag represents introductory content or navigation links.",
    hint: "Type <header> to open the header section.",
    desc: "Create an opening header tag.",
    check: function(input) {
        var clean = input.toLowerCase().replace(/\s+/g, '');
        return clean.indexOf("<header>") !== -1;
    }
}

إرشادات تصميم التحقق من الصحة
عند إضافة قواعد التحقق، حافظ على قواعد التوافق الشاملة للمشروع:
 * استخدم عمليات السلاسل النصية القياسية: اعتمد على دوال مثل .indexOf()، و .toLowerCase()، والتعابير النمطية الأساسية (Regular expressions).
 * التعامل مع المسافات البيضاء بمرونة: تجنب مقارنات السلاسل النصية الصارمة التي قد تفشل بسبب المسافات الزائدة في النهاية أو فواصل الأسطر.
 * الحفاظ على التوافق: لا تقم بتقديم طرق ES6 (مثل .includes()) ما لم يتم توفير حشو داعم لها (Polyfill) أصلياً داخل الملف.
