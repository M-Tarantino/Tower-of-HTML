Phase 0: Introduction

Floor 0: Overview & Instructions

Learning Objective: Introduce learners to the Tower of HTML and explain the game mechanics.

What You're Learning: - How the game works - What HTML is and why it matters - The structure of the tower progression

Deep Explanation:

HTML (HyperText Markup Language) is the foundation of every website on the internet. It's the language that browsers read to understand what content to display and how to structure it.

Think of HTML as the blueprint of a building: - The blueprint tells builders where walls go, where doors go, where windows go - HTML tells browsers where text goes, where images go, what are headings and paragraphs, etc.

Why Learn HTML? 1. Foundation Skill - Every web developer starts with HTML 2. Accessible - No special software needed, works everywhere 3. Powers the Web - Every single website you visit uses HTML 4. Gateway to Web Dev - Once you know HTML, you can learn CSS (styling) and JavaScript (interactivity)

Real-World Context: - A website without HTML is like a book without pages - HTML is used by websites, apps, emails, and even ebooks - It's a skill that will remain valuable for decades

Best Practice: - Semantic HTML (using correct tags for the right content) matters more than you might think - Clean HTML makes styling and functionality easier later - Accessibility starts with proper HTML structure

Player Entry Mechanism: - Players must type "START" to enter the tower - This teaches case-insensitivity and basic instruction following

Phase 1: Foundation (Levels 1-9)

Floor 1: The Root Element

Learning Objective: Understand that every HTML document needs an <html> tag as its root container.

Concept: HTML Tag Structure

An HTML tag is how you give instructions to the browser. Tags have this format:

<tagname>content</tagname>

The < and > are bracket symbols that mark the beginning and end of a tag instruction. The text between them is the tag's name.

The <html> Tag - The Root Element

Every single HTML document must start with <html> (and end with </html>). This tag is called the root element because: - It contains everything else - It's the starting point (root) of the HTML structure - All other tags must go inside it

Think of it like a book: - The book <html> contains all chapters (head and body) - Everything else is inside the book

Why This Matters: - Browsers specifically look for <html> to know "this is an HTML document" - Without it, the browser might misinterpret the content - It's the contract between you (the developer) and the browser

Scope in Page:

<html>
  <!-- Everything else goes here -->
</html>

Common Mistakes: - Forgetting to close the tag with </html> - Putting things outside the <html> tag (except DOCTYPE - more on that later) - Misspelling as <HTML> (browsers are forgiving but it's not best practice)

Real-World Use: - Every HTML file you download has this structure - Open any website's source code (Ctrl+U or right-click → View Page Source) and you'll see it starts with <html>

Floor 2: Close HTML

Learning Objective: Understand closing tags and proper tag structure.

Concept: Opening and Closing Tags

HTML uses pairs of tags: - Opening tag: <html> - starts the element - Content: Everything between the tags - Closing tag: </html> - ends the element

The closing tag is identical to the opening tag but has a / (forward slash) after the <.

Why Closing Tags Matter:

HTML is hierarchical and nested. The closing tag tells the browser "this element is done now."

Nesting Principle:

<html>
  <head>
    <!-- content -->
  </head>
  <body>
    <!-- content -->
  </body>
</html>

If you open a tag, you must close it. Think of it like parentheses in math: - (2 + 3) must have both opening and closing parenthesis - Similarly, <html> and </html> must both exist

Self-Closing Tags (Advanced Note):

Some HTML tags don't need a closing tag because they don't have content:

<img src="photo.jpg">  <!-- image tag - can't have content -->
<br>                    <!-- line break - can't have content -->

But these are exceptions. Most tags (like <html>, <head>, <p>, etc.) require closing tags.

Common Mistakes: - Forgetting the closing tag - Putting closing tags in wrong order: <html><head></html></head> ❌ (correct: <html><head></head></html> ✓) - Using wrong slash direction: <html> vs \html (backslash doesn't work)

Floor 3: Head Section

Learning Objective: Learn that HTML documents have two main parts: head and body.

Concept: Document Structure - Head Section

An HTML document is divided into two main sections:

  1. <head> - The invisible control center
  2. Contains settings, metadata, links to styles

  3. Nothing here displays on the page directly

  4. <body> - The visible content

  5. Contains text, images, videos
  6. Everything users see

What is Metadata?

Metadata means "data about data" - information that describes your document:

Metadata Example Purpose
Title <title>My Website</title> Shows in browser tab, search results
Charset <meta charset="UTF-8"> Tells browser which characters to support
Description <meta name="description" content="..."> Used by search engines
Author <meta name="author" content="John"> Who created the page
Viewport <meta name="viewport"> How to display on mobile devices

Structure:

<html>
  <head>
    <!-- All metadata goes here -->
    <!-- Users never see this section -->
  </head>
  <body>
    <!-- All visible content goes here -->
    <!-- Users see everything here -->
  </body>
</html>

Why This Matters:

The head section is what makes websites: - Appear correctly in search engines (SEO) - Look right on phones - Display the correct title in the browser tab - Handle different languages and character sets

Real-World Example:

When you share a link on Facebook or Twitter, where does it get the preview image and description? From the <head> metadata!

Browser Behavior:

  • Browsers process the <head> before rendering anything
  • If <head> has an error, the page might not display correctly
  • Style sheets in <head> affect how the <body> looks

Floor 4: Title Tag

Learning Objective: Understand the <title> tag and its importance.

Concept: The <title> Tag

The <title> tag does exactly one thing: Sets the name of the webpage.

Where Does It Show?

Browser Tab: [My Awesome Website ✕]
                ↑
            Title goes here

Also appears in: - Browser history - Bookmarks - Search engine results (as the clickable headline)

Structure:

<head>
  <title>My Awesome Website</title>
</head>

Best Practices:

  1. Be Specific:
  2. ❌ Bad: <title>Home</title>

  3. ✓ Good: <title>Welcome to John's Photography Portfolio</title>

  4. Keep It Short:

  5. Search engines cut off titles around 50-60 characters

  6. Mobile browsers show even less

  7. Front-Load Keywords:

  8. ✓ <title>Best Pizza in New York | Tony's Pizzeria</title>

  9. ❌ <title>About Us | Tony's Pizzeria | New York Pizza</title>

  10. Unique Per Page:

  11. Each page should have its own title
  12. Home page, about page, contact page - all different

Real-World Impact:

Your title tag directly affects: - SEO (Search Engine Optimization) - How high your site ranks - Click-through Rate - People decide to click based on the title - User Experience - Users can find their tabs if they're named well

Common Mistakes: - Empty title tags - Using same title for every page - Making it too long (gets cut off) - Not using keywords relevant to page content

Floor 5: Close Head

Learning Objective: Understand the head section is complete, everything else goes in body.

Review: Head Closure

Just like </html> closes the root element, </head> closes the head section.

Structure So Far:

<html>
  <head>
    <title>My Page</title>
    <!-- Other metadata could go here -->
  </head>
  <!-- Body will go next -->
</html>

Important Principle:

Once you close </head>, the browser knows: - "I'm done with invisible settings" - "Now get ready to display visible content" - "Everything after this is what users see"

Nesting Validation:

<html>           ← opens
  <head>         ← opens
    <title>...</title>
  </head>        ← closes head (still inside html)
</html>          ← closes html (everything inside is part of it)

Notice the proper nesting: Close tags in reverse order of opening them.

Floor 6: Body Section

Learning Objective: Understand the <body> tag contains all visible content.

Concept: The <body> Tag

If <head> is the control center, <body> is the actual content people come to see.

What Goes In Body: - Headings (titles, subtitles) - Paragraphs (text content) - Images - Videos - Links - Buttons - Forms - Lists - Tables - Any visible content

What Stays In Head: - Title - Metadata - Links to stylesheets - Scripts - Any invisible configuration

Structure:

<html>
  <head>
    <title>Welcome</title>
  </head>
  <body>
    <!-- Everything users see goes here -->
  </body>
</html>

Browser Rendering:

  1. Browser reads <head> → Loads styles, sets title, prepares
  2. Browser reads <body> → Renders and displays content
  3. User sees a complete webpage

Scope and Nesting:

<body>
  <h1>Main Heading</h1>
  <p>Paragraph text</p>
  <img src="photo.jpg">
  <!-- All visible content nested here -->
</body>

Everything users see is directly inside <body> or nested inside elements that are inside <body>.

Size Matters:

  • <body> is usually the largest section of your HTML
  • A simple page might have 50 lines in body vs 10 in head
  • A complex page could have thousands of lines in body

Floor 7: Heading Element

Learning Objective: Learn to create headings and understand heading hierarchy.

Concept: The <h1> Tag - Main Heading

<h1> creates the most important heading on a page. Think of it as the title of a document or main topic.

Heading Hierarchy in HTML:

<h1>Main Topic</h1>          ← Largest, most important
<h2>Subtopic</h2>            ← Smaller, less important
<h3>Sub-subtopic</h3>        ← Even smaller
<h4>Detail</h4>
<h5>Minor Detail</h5>
<h6>Tiny Detail</h6>         ← Smallest, least important

Visual Representation:

<h1>← Big and important
  <h2>← Medium importance
    <h3>← Smaller
      <h4>← Even smaller

Why Heading Hierarchy Matters:

  1. For Users:
  2. Headings help people scan the page quickly

  3. Users find what they want faster

  4. For Accessibility:

  5. Screen readers use headings to help blind users understand page structure

  6. Without proper headings, websites are harder to use

  7. For Search Engines:

  8. Google uses <h1> and <h2> to understand page topic

  9. This affects SEO ranking

  10. For Styling:

  11. Each heading level can be styled differently with CSS
  12. <h1> usually larger, bold
  13. <h2> slightly smaller
  14. etc.

Best Practices:

<!-- ✓ Correct hierarchy -->
<h1>My Blog</h1>
  <h2>First Article</h2>
  <h2>Second Article</h2>
    <h3>Sub-point of second article</h3>

<!-- ❌ Wrong - skipping levels -->
<h1>My Blog</h1>
<h3>Article</h3>  <!-- Should be <h2>, not <h3> -->

One H1 Per Page:

Best practice is to have only one <h1> per page (the main topic). You can have multiple <h2>, <h3>, etc., but only one <h1>.

Real-World Example:

Imagine a news website:

<h1>Daily News</h1>              <!-- Main topic -->
  <h2>Politics</h2>              <!-- Section -->
    <h3>Election Results</h3>
    <h3>New Laws</h3>
  <h2>Sports</h2>                <!-- Another section -->
    <h3>Football</h3>
    <h3>Basketball</h3>

Floor 8: Paragraph

Learning Objective: Learn to create text content using paragraphs.

Concept: The <p> Tag - Paragraph

<p> is how you write normal text content. Any text you want to display to users should usually go inside a <p> tag.

Structure:

<body>
  <h1>My Article</h1>
  <p>This is the first paragraph of text.</p>
  <p>This is the second paragraph of text.</p>
</body>

What <p> Does:

  1. Groups text together - Multiple sentences form one concept
  2. Adds spacing - Browsers automatically add space before and after
  3. Makes it semantic - Tells browsers "this is a paragraph, not a heading"

Display in Browser:

My Article
This is the first paragraph of text.

This is the second paragraph of text.

Notice the automatic spacing between paragraphs.

Why Not Just Type Text?

You might think:

<body>
Today is a nice day.
Tomorrow will be sunny.
</body>

But this is bad because: - Browsers treat it as "random text" with no structure - Screen readers don't know it's meant to be read - Styling is harder to apply - It's not semantically correct

Correct Approach:

<body>
  <p>Today is a nice day.</p>
  <p>Tomorrow will be sunny.</p>
</body>

Common Mistakes:

  1. Nested paragraphs (not allowed): ```html

    Text

    More text

❌ Don't do this ```

  1. Using paragraphs for spacing: ```html

    Some content

❌ Empty paragraphs for spacing

More content

``` Use CSS margins instead.

  1. Breaking sentences into multiple paragraphs: ```html

    This is the first sentence.

This is the second sentence.

❌ Should be one paragraph ```

Real-World Example:

A blog post:

<h1>How to Learn HTML</h1>
<p>Learning HTML is the first step to web development. It's the foundation of everything on the web.</p>
<p>HTML stands for HyperText Markup Language. It was created in 1989 by Tim Berners-Lee at CERN.</p>
<h2>Getting Started</h2>
<p>To get started, you need a text editor and a web browser. No special software required!</p>

Floor 9: Close Body

Learning Objective: Complete the basic HTML structure.

Review: Closing Body

</body> closes the body section. After this, only </html> remains.

Complete Basic Structure:

<html>
  <head>
    <title>My First Page</title>
  </head>
  <body>
    <h1>Welcome!</h1>
    <p>This is my first webpage.</p>
  </body>
</html>

What You've Built:

Congratulations! At this point, you understand: - ✓ <html> - The root container - ✓ <head> - Invisible metadata - ✓ <title> - Webpage name - ✓ <body> - Visible content - ✓ <h1> - Main heading - ✓ <p> - Paragraph text - ✓ Closing tags - ✓ Nesting structure

This is the fundamental structure that every single website uses.

Validation Check:

<html>           ← opened
  <head>         ← opened
    ...
  </head>        ← closed
  <body>         ← opened
    ...
  </body>        ← closed
</html>          ← closed

All tags properly opened and closed in correct order. ✓

Phase 2: Text Content (Levels 10-20)

Floor 10: Strong Text

Learning Objective: Learn to emphasize important text.

Concept: The <strong> Tag

<strong> makes text important or heavily emphasized.

Display:

<p>This is <strong>very important</strong> information.</p>

Browser displays as: This is very important information.

Why Not Just Use Bold in Word?

In Microsoft Word, you can press Ctrl+B to make text bold. But HTML is different: - HTML describes meaning, not just appearance - <strong> means "this is important" (meaning) - Bold is just how browsers show importance (appearance)

This distinction matters for: - Screen readers - They emphasize <strong> differently - Search engines - They recognize <strong> text as important - Styling - Different devices might show importance differently

Real-World Use:

<p>This product is <strong>out of stock</strong>.</p>
<p><strong>Warning:</strong> This medication has side effects.</p>
<p>Please read the <strong>terms and conditions</strong> before purchasing.</p>

Semantic HTML Principle:

HTML tags should describe what content means, not how it looks. - ✓ <strong> = "This is important" - ❌ <b> = "This is bold" (describes appearance, not meaning)

(Note: <b> exists for stylistic bolding, but <strong> is better for meaning.)

Floor 11: Emphasis (Italic)

Learning Objective: Learn to emphasize text with italics.

Concept: The <em> Tag

<em> provides emphasis - typically shown as italic text.

Display:

<p>This is <em>emphasized</em> text.</p>

Browser displays as: This is emphasized text.

Strong vs. Emphasis:

<strong>This is important/serious</strong>
<em>This deserves attention/pause</em>
<strong> <em>
Important Emphasized
Critical information Deserves a pause
Warning, urgency Tone change
"This matters" "Notice this"

Examples:

<p>This deadline is <strong>critical</strong>.</p>
<p>I <em>really</em> love this color.</p>
<p><strong>Warning:</strong> Do <em>not</em> ignore this.</p>

Screen Reader Behavior:

Screen readers will: - Raise voice or change tone for <strong> - Pause or change inflection for <em>

This helps users with visual impairments understand the nuance.

Floor 12: Line Break

Learning Objective: Understand when to use <br> and when not to.

Concept: The <br> Tag - Line Break

<br> creates a line break (forces text to a new line).

Usage:

<p>
  123 Main Street<br>
  New York, NY 10001<br>
  USA
</p>

Displays as:

123 Main Street
New York, NY 10001
USA

Special Property: Self-Closing Tag

<br> is one of the few HTML tags that doesn't have a closing tag. You just use <br> (or <br/> with a slash, both work).

When to Use <br>:

  1. Addresses: Line-by-line format matters
  2. Poetry: Each line is intentional
  3. Lyrics: Line breaks are part of the content
  4. Form fields: After input labels sometimes
<p>
  <strong>Shipping Address:</strong><br>
  John Smith<br>
  456 Oak Avenue<br>
  Los Angeles, CA 90001
</p>

When NOT to Use <br>:

❌ WRONG - Using <br> for spacing:

<p>First paragraph</p>
<br>
<br>
<br>
<p>Second paragraph</p>

✓ CORRECT - Use CSS for spacing:

<p>First paragraph</p>
<p>Second paragraph</p>

Then use CSS: p { margin: 20px 0; }

Why This Matters:

  • <br> is a content element (the line break is part of the content)
  • CSS spacing is for design (how the page looks)
  • Mixing them makes code hard to maintain

Floor 13: Horizontal Rule

Learning Objective: Learn to create visual separators.

Concept: The <hr> Tag

<hr> creates a horizontal rule - a line that visually separates content.

Display:

<h2>Section 1</h2>
<p>Content here...</p>

<hr>

<h2>Section 2</h2>
<p>More content...</p>

Displays as:

Section 1
Content here...
_____________________________
Section 2
More content...

Self-Closing Tag:

Like <br>, <hr> is self-closing. Use <hr> or <hr/>.

When to Use:

  • Separate major sections
  • Visual break in content flow
  • Between related but distinct topics

When NOT to Use:

❌ WRONG - Using <hr> for design:

<h2>Navigation</h2>
<hr>
<a href="/">Home</a> | <a href="/about">About</a>
<hr>

Use CSS borders instead.

Semantic Note:

<hr> represents a thematic break in content, not just a visual line. Use it when the topic or context changes significantly.

Floor 14: Code Display

Learning Objective: Display code snippets in text.

Concept: The <code> Tag

<code> displays text as computer code (usually in monospace font like Courier).

Usage:

<p>To print hello, use <code>console.log("hello");</code></p>

Displays as: To print hello, use console.log("hello");

When to Use:

  • Short code snippets inline (like above)
  • Variable names: "Set the variable count"
  • Function names: "Call the getUserById() function"
  • HTML tags being discussed: "Use <div> for containers"

Multiple Lines - <pre> Tag:

For longer code blocks, use <pre> (preformatted) which preserves spaces and line breaks:

<pre><code>
function helloWorld() {
  console.log("Hello, World!");
  return true;
}
</code></pre>

The <code> inside <pre> indicates it's code, and <pre> preserves formatting.

Visual Distinction:

  • <code> - Inline code (within text)
  • <pre><code> - Block of code (standalone)

Accessibility Consideration:

Always describe what the code does, not just show it:

✓ GOOD:

<p>Function to calculate sum: 
<code>sum = a + b;</code></p>

❌ POOR:

<p><code>sum = a + b;</code></p>

Floor 15: Deleted and Inserted Text

Learning Objective: Show text changes with <del> and <ins>.

Concept: Tracking Changes

<del> shows deleted text (struck through). <ins> shows inserted text (underlined).

Usage:

<p>The event is on <del>Friday</del> <ins>Saturday</ins> at 3pm.</p>

Displays as: The event is on ~~Friday~~ Saturday at 3pm.

Real-World Use Cases:

  1. Version tracking:
<p>Price: <del>$99</del> <ins>$79</ins></p>
  1. Document changes:
<p>We will <del>accept</del> <ins>no longer accept</ins> payment by check.</p>
  1. Edit history:
<p>Our headquarters is located in <del>New York</del> <ins>San Francisco</ins>.</p>

Advanced: The datetime Attribute

You can add when the change was made:

<p>Event date: <del datetime="2025-01-15">Friday</del> 
<ins datetime="2025-01-15">Saturday</ins></p>

The datetime helps track when changes happened (useful for blogs, wikis, documentation).

Floor 16: Subscript and Superscript

Learning Objective: Format scientific and mathematical notation.

Concept: <sub> and <sup>

  • <sub> - Subscript (below baseline, smaller)
  • <sup> - Superscript (above baseline, smaller)

Usage:

<p>Water is H<sub>2</sub>O</p>
<p>The area formula is A = πr<sup>2</sup></p>

Displays as: - Water is H₂O - The area formula is A = πr²

When to Use:

  1. Chemistry:
<p>Glucose: C<sub>6</sub>H<sub>12</sub>O<sub>6</sub></p>
<p>Sulfuric acid: H<sub>2</sub>SO<sub>4</sub></p>
  1. Mathematics:
<p>x<sup>2</sup> + y<sup>2</sup> = z<sup>2</sup></p>
<p>e = mc<sup>2</sup></p>
  1. Footnotes:
<p>According to Einstein<sup>*</sup>, everything is relative.</p>
<p><sup>*</sup> <em>Theory of Relativity, 1915</em></p>

Important: These are semantic tags for meaning, not just visual styling. Use them when subscript/superscript is actually part of the content.

Floor 17: Highlighting Important Text

Learning Objective: Mark text for emphasis or highlight.

Concept: The <mark> Tag

<mark> highlights text (typically yellow background).

Usage:

<p>The most important point is <mark>this one</mark> in my opinion.</p>

Real-World Use:

  1. Search results:
<p>HTML is a <mark>markup language</mark> for creating web pages.</p>

(The search term would be highlighted)

  1. Study guides:
<p>The Roman Empire fell in <mark>476 AD</mark>.</p>
  1. Highlighting key info:
<p>Registration closes <mark>December 31, 2025</mark>!</p>

Difference from <strong>:

<strong> <mark>
Important Highlighted for reference
Semantic importance Visual highlighting
Bold appearance Usually yellow highlight

Floor 18: Lists - Unordered

Learning Objective: Create bulleted lists.

Concept: The <ul> and <li> Tags

  • <ul> = Unordered List (bulleted)
  • <li> = List Item (individual item)

Usage:

<h2>Shopping List</h2>
<ul>
  <li>Apples</li>
  <li>Bread</li>
  <li>Milk</li>
</ul>

Displays as:

Shopping List
• Apples
• Bread
• Milk

When to Use:

  • No particular order needed
  • Just collecting related items
  • Shopping lists, ingredients, features, benefits

Proper Nesting:

<ul>
  <li>Item 1</li>
  <li>Item 2</li>
  <li>Item 3</li>
</ul>

Every <li> must be directly inside a <ul>.

Nested Lists:

<ul>
  <li>Fruits
    <ul>
      <li>Apples</li>
      <li>Bananas</li>
    </ul>
  </li>
  <li>Vegetables
    <ul>
      <li>Carrots</li>
      <li>Broccoli</li>
    </ul>
  </li>
</ul>

Floor 19: Lists - Ordered

Learning Objective: Create numbered lists.

Concept: The <ol> Tag

<ol> = Ordered List (numbered, order matters)

Usage:

<h2>Recipe Steps</h2>
<ol>
  <li>Preheat oven to 350°F</li>
  <li>Mix flour and sugar</li>
  <li>Add eggs and milk</li>
  <li>Bake for 30 minutes</li>
</ol>

Displays as:

Recipe Steps
1. Preheat oven to 350°F
2. Mix flour and sugar
3. Add eggs and milk
4. Bake for 30 minutes

When to Use:

  • Steps in a process (order matters!)
  • Rankings or priorities
  • Instructions or tutorials
  • Top 10 lists

Unordered vs Ordered:

<!-- ✓ Ordered - steps must happen in sequence -->
<ol>
  <li>Boot computer</li>
  <li>Open application</li>
  <li>Create file</li>
</ol>

<!-- ✓ Unordered - no particular order -->
<ul>
  <li>HTML knowledge required</li>
  <li>Text editor needed</li>
  <li>Web browser recommended</li>
</ul>

Floor 20: Abbreviations and Definitions

Learning Objective: Mark abbreviations and define terms.

Concept: The <abbr> Tag

<abbr> marks abbreviations with the full meaning.

Usage:

<p>The <abbr title="Hypertext Markup Language">HTML</abbr> 
specification is maintained by the <abbr title="World Wide Web Consortium">W3C</abbr>.</p>

When users hover over "HTML" or "W3C", they see the full name.

Key Feature: The title Attribute

The title attribute holds the expanded version. On hover, it displays: - HTML → "Hypertext Markup Language" - W3C → "World Wide Web Consortium"

Real-World Examples:

<p>I work at <abbr title="National Aeronautics and Space Administration">NASA</abbr>.</p>

<p>The <abbr title="Application Programming Interface">API</abbr> allows third-party access.</p>

<p>Send feedback to <abbr title="Customer Service">CS</abbr> team.</p>

Accessibility Benefit:

Screen readers announce the full term on first use, helping users understand what the abbreviation means.

Phase 3: Semantic HTML (Levels 21-30)

Floor 21: Header Element

Learning Objective: Learn semantic structure with header elements.

Concept: The <header> Tag

<header> contains introductory content for a page or section (logo, title, navigation).

Usage:

<header>
  <h1>My Blog</h1>
  <p>Welcome to my thoughts on web development</p>
</header>

Common Contents:

<header>
  <img src="logo.png" alt="Company Logo">
  <h1>Company Name</h1>
  <nav>
    <a href="/">Home</a>
    <a href="/about">About</a>
    <a href="/contact">Contact</a>
  </nav>
</header>

Page Header vs Section Header:

<body>
  <header>
    <!-- Site-wide header -->
    <h1>My Website</h1>
  </header>

  <main>
    <article>
      <header>
        <!-- Article-specific header -->
        <h2>Article Title</h2>
        <p>By John Doe, January 15, 2025</p>
      </header>
      <p>Article content...</p>
    </article>
  </main>
</body>

Why Semantic?

  • Tells search engines "this is introductory content"
  • Screen readers announce "header" separately
  • Easier for developers to understand code structure
  • Better CSS styling targeting

Floor 22: Navigation Element

Learning Objective: Mark navigation menus properly.

Concept: The <nav> Tag

<nav> contains navigation links.

Usage:

<nav>
  <a href="/">Home</a>
  <a href="/products">Products</a>
  <a href="/about">About</a>
  <a href="/contact">Contact</a>
</nav>

Navigation Patterns:

  1. Main navigation:
<header>
  <h1>Company</h1>
  <nav>
    <a href="/">Home</a>
    <a href="/products">Products</a>
  </nav>
</header>
  1. Footer navigation:
<footer>
  <nav>
    <a href="/privacy">Privacy Policy</a>
    <a href="/terms">Terms</a>
  </nav>
</footer>
  1. Breadcrumb navigation:
<nav>
  <a href="/">Home</a> > 
  <a href="/products">Products</a> > 
  <a href="/products/widget">Widget</a>
</nav>

Accessibility:

  • Screen readers announce "navigation" when encountering <nav>
  • Users can skip to navigation with keyboard shortcuts
  • Better structure for assistive technologies

Floor 23: Main Content

Learning Objective: Mark primary page content.

Concept: The <main> Tag

<main> contains the primary content of the page.

Usage:

<body>
  <header>Navigation stuff</header>

  <main>
    <!-- The main content goes here -->
    <article>Article content</article>
  </main>

  <footer>Footer stuff</footer>
</body>

Rules for <main>:

  1. Only one <main> per page
  2. Should not be nested inside <header>, <footer>, <nav>, <article>, or <aside>
  3. Contains the primary content (not sidebars or auxiliary content)

Page Layout Example:

<body>
  <header>
    <h1>My News Site</h1>
    <nav>Links...</nav>
  </header>

  <main>
    <article>Breaking News: XYZ Happens</article>
    <article>Another Story</article>
  </main>

  <aside>
    <h2>Trending Topics</h2>
    Related links...
  </aside>

  <footer>
    <p>Copyright 2025</p>
  </footer>
</body>

Floor 24: Article Element

Learning Objective: Wrap article/post content.

Concept: The <article> Tag

<article> wraps self-contained content (blog post, news article, forum post).

Usage:

<article>
  <h2>How to Learn HTML</h2>
  <p>By Jane Doe, September 10, 2025</p>
  <p>HTML is the foundation of web development...</p>
  <p>To get started, you need a text editor...</p>
</article>

Key Characteristic:

Content in <article> could stand alone (could be copied to another website and still make sense).

Examples of <article>:

  • Blog posts
  • News articles
  • Forum posts
  • Comments
  • Product reviews

Examples NOT for <article>:

  • Header or footer content
  • Navigation menus
  • Sidebar widgets
  • Generic sections

Multiple Articles:

<main>
  <article>
    <h2>First Article</h2>
    Content...
  </article>

  <article>
    <h2>Second Article</h2>
    Content...
  </article>
</main>

Floor 25: Section Element

Learning Objective: Group thematically related content.

Concept: The <section> Tag

<section> groups thematically related content together.

Usage:

<section>
  <h2>Fruits</h2>
  <p>Information about fruits...</p>
</section>

<section>
  <h2>Vegetables</h2>
  <p>Information about vegetables...</p>
</section>

Section vs Article:

<section> <article>
Thematic grouping Self-contained content
Part of a page Standalone piece
Related material Could be elsewhere
Generic grouping Specific type of content

Example:

<article>
  <h1>Web Development Guide</h1>

  <section>
    <h2>HTML Basics</h2>
    <p>HTML is...</p>
  </section>

  <section>
    <h2>CSS Styling</h2>
    <p>CSS allows...</p>
  </section>

  <section>
    <h2>JavaScript Interactivity</h2>
    <p>JavaScript makes...</p>
  </section>
</article>

Tag Purpose Example

Phase 4: Links & Media (Levels 31-40)

Floor 31: Hyperlinks - The <a> Tag

Learning Objective: Create clickable links.

Concept: The <a> Tag

<a> creates hyperlinks (the thing you click to go somewhere).

Usage:

<a href="https://example.com">Click here</a>

The href Attribute:

href = "Hypertext Reference" - where the link goes.

Types of Links:

  1. External links (to other websites):
<a href="https://www.wikipedia.org">Learn more on Wikipedia</a>
  1. Internal links (within your site):
<a href="/about">About Us</a>
<a href="/products/widget">Widget Product</a>
  1. Email links:
<a href="mailto:contact@example.com">Email us</a>
  1. Phone links:
<a href="tel:+1-555-123-4567">Call us</a>
  1. Anchor links (jump to section):
<a href="#section2">Go to Section 2</a>

Link Text Best Practices:

✓ GOOD - Descriptive:

<a href="/about">Learn more about our company</a>

❌ BAD - Generic:

<a href="/about">Click here</a>

Why? Screen readers and search engines use link text to understand where links go.

Floor 32: Images - The <img> Tag

Learning Objective: Embed images.

Concept: The <img> Tag

<img> embeds images on a page.

Usage:

<img src="photo.jpg" alt="My Family Photo">

Key Attributes:

  1. src - Image file path
  2. alt - Alternative text (shown if image fails to load)

The alt Attribute - Critical for Accessibility:

<!-- ✓ Good - describes the image -->
<img src="sunset.jpg" alt="Orange sunset over the ocean">

<!-- ❌ Bad - no description -->
<img src="sunset.jpg">

<!-- ❌ Bad - too generic -->
<img src="sunset.jpg" alt="image">

The alt text should describe what the image shows, so blind users and search engines understand it.

Image Formats:

  • JPG - Photos and complex images
  • PNG - Graphics, logos, images with transparency
  • GIF - Animated images
  • WebP - Modern format, smaller file size

Image Sizing:

<img src="photo.jpg" alt="Beach photo" width="400" height="300">

Responsive Images (Modern Approach):

<img 
  src="photo.jpg" 
  alt="Beach"
  style="max-width: 100%; height: auto;"
>

Tag Purpose Example

<source> Multiple formats Inside <video> or <audio>
<track> Subtitles/captions <track src="subs.vtt" kind="subtitles">
<iframe> Embed external content YouTube, maps, etc.

Key Concepts Reference

HTML Document Flow

  1. DOCTYPE - Tells browser this is HTML5
  2. <html> - Root element wrapper
  3. <head> - Metadata container
  4. <title> - Page title
  5. <meta> - Various metadata
  6. <link> - External resources (CSS)
  7. <script> - Inline scripts
  8. <body> - Visible content
  9. Headings (<h1>-<h6>)
  10. Paragraphs (<p>)
  11. Links (<a>)
  12. Images (<img>)
  13. Lists (<ul>, <ol>)
  14. Tables (<table>)
  15. And more...

Fundamental Principles

  1. Semantic HTML - Use tags that describe meaning, not appearance
  2. Proper Nesting - Open and close tags correctly
  3. Accessibility First - Code so it works for everyone
  4. Progressive Enhancement - Content works without CSS/JavaScript
  5. Separation of Concerns - HTML (structure), CSS (styling), JS (behavior)

Best Practices Summary

  1. ✓ Use semantic tags (<article>, <section>, <nav>)
  2. ✓ Write valid, well-formed HTML
  3. ✓ Include proper meta tags
  4. ✓ Use alt text for images
  5. ✓ Use heading hierarchy correctly
  6. ✓ Write clean, indented code
  7. ✓ Use meaningful class/id names
  8. ✓ Don't use deprecated tags

Common Mistakes to Avoid

  1. ❌ Forgetting closing tags
  2. ❌ Improper nesting
  3. ❌ Using tags for styling instead of structure
  4. ❌ Skipping accessibility features
  5. ❌ Invalid attribute values
  6. ❌ Not validating code
  7. ❌ Using outdated HTML4 syntax
  8. ❌ Mixing content with presentation

Translation Notes

This guide serves as the canonical English reference for translating Tower of HTML into any language. When translating:

  1. Preserve code examples - Never translate code, only explanatory text

  3. Keep structure identical - Same headings, same organization
  4. Localize examples - Addresses, names, examples can be localized
  5. Maintain technical accuracy - Don't simplify technical concepts incorrectly
